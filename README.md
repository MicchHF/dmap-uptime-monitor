# Мониторинг D‑Map на Render

Чекер отправляет уведомления через Telegram-бота в один или два личных чата. Раз в две минуты проверяет HTTPS для карты, кабинета и `/map/health`. После двух неудачных проверок подряд отправляет одно сообщение со списком проблем. После восстановления отправляет ещё одно. Основной сервер D‑Map используется только для чтения этих общедоступных страниц.

Проверка видит доступность из региона Render. Она может пропустить сбой, который затрагивает только отдельного оператора или VPN. Проверка кабинета подтверждает отдачу страницы входа. Работу входа, клиентского JavaScript и карты внутри Telegram она не измеряет.

## Подготовить Telegram

1. Выбери бота в `/mybots` у [BotFather](https://t.me/BotFather) и возьми его токен. Можно использовать ранее созданного бота. Если он ещё связан со старым приложением, проверь, что оно отключено.
2. Каждый получатель открывает бота в личном чате и нажимает **Start**. Если числовые ID личных чатов уже известны, используй их. Чтобы узнать ID, установи зависимости в папке пакета на ПК и запусти помощник. Для одного получателя используй ту же команду без `--two`.

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe pair.py --two
   ```

   Помощник запросит токен со скрытым вводом. В консоли появятся две одноразовые команды. Каждый получатель отправляет свою команду целиком, включая код после `/start`, в личном чате с ботом. Через десять минут коды перестанут приниматься. После привязки в консоли появится значение `TELEGRAM_CHAT_IDS`. Храни токен бота в настройках Render. Если у бота ещё настроен вебхук старого приложения, помощник остановится и сообщит об этом. Известные ID можно указать напрямую.

## Настроить Render

1. Создай **Key Value → Free** в том же регионе, где будет чекер, или используй уже доступный подходящий экземпляр. Возьми **Internal URL**. Состояние хранится отдельно от веб-сервиса. Если бесплатный Key Value сам перезапустится, счётчик начнётся с нуля и для продолжающегося сбоя может прийти повторное уведомление.
2. Создай **Web Service → Free**. Исходники этого пакета можно подключить из отдельного репозитория GitLab или задать собранный образ через **Existing Image**. Для образа используй `Dockerfile` из этой папки. Если выбран Python из репозитория, используй команды ниже. Если папка `render-monitor` вложена в репозиторий, укажи её как **Root Directory**.

   - **Build Command** · `pip install -r requirements.txt`
   - **Start Command** · `gunicorn --bind 0.0.0.0:$PORT --workers 2 --timeout 24 'monitor:create_app()'`
   - **Health Check Path** · `/healthz`

3. Добавь переменные в **Environment**.

   | Имя | Значение |
   | --- | --- |
   | `REDIS_URL` | Внутренний URL Key Value |
   | `TELEGRAM_BOT_TOKEN` | Токен выбранного бота от BotFather |
   | `TELEGRAM_CHAT_IDS` | Один или два числовых ID личных чатов через запятую, например `123456789,987654321` |
   | `CHECK_TOKEN` | Случайный секрет только для чекера. Создай его командой `python -c "import secrets; print(secrets.token_urlsafe(32))"` |

   После запуска `https://<сервис>.onrender.com/healthz` должен вернуть `{"ok": true}`.

## Настроить расписание и проверить доставку

1. В [cron-job.org](https://cron-job.org/) создай задачу раз в **2 минуты** на `https://<сервис>.onrender.com/check`. Выбери метод **POST**, тело оставь пустым и добавь заголовок **Authorization** со значением `Bearer <CHECK_TOKEN>`. Секрет вводи в заголовок. Уведомления cron-job.org о сбое задачи пригодятся для отдельного контроля расписания и самого чекера.
2. Запусти пробную задачу с теми же методом и заголовком по пути `/test-alert`. Ожидаются статус `test_sent` и сообщение у каждого указанного получателя. Удали пробную задачу после проверки. Если Render только проснулся, дождись ответа от `/healthz` и повтори тест.
3. Проверь в истории расписания, что очередные запросы к `/check` выполняются. При исправном сайте результат `healthy`. При сбое сайта результат `degraded` содержит список проблем. Если Telegram не принял уведомление для одного из получателей, чекер повторит попытку только для этого чата при следующей подходящей проверке. При ошибке Telegram или хранилища чекер отвечает HTTP 503, чтобы сбой мониторинга был виден в истории.

Бесплатный Render засыпает после 15 минут без входящих запросов. Регулярные проверки поддерживают его активность и расходуют общий лимит в 750 часов в месяц на рабочее пространство. Один круглосуточный сервис занимает до 744 часов. Первый вызов после сна может длиться дольше лимита cron-job.org в 30 секунд.
